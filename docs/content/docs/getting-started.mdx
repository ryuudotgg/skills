## Install

Prerequisites: git, gh and Bun 1.4.0 or newer. Installing needs no Python.

```sh
git clone https://github.com/ryuudotgg/skills && cd skills && ./install.sh
```

`install.sh` symlinks this checkout's `skills/` into the canonical store at `~/.agents/skills`, then links those skills into the agent tool directories it finds. It creates `~/.claude/skills` when `~/.claude` exists, and `~/.codex/skills` when `~/.codex` exists. It also links into existing `~/.cursor/skills`, `~/.config/opencode/skills`, and `~/.copilot/skills` directories without creating them.

With no flags other than `--verbose`, stdin and stdout at a terminal, and `CI` unset, `skills install` asks for the delivery mode and optional reviewers. When the Claude or Codex directory exists, it then asks for Deny, Ask, Customize or Don't manage and saves `AGENT_RULES` in `skills.conf`. Rule changes are previewed before you confirm. Canceling changes no skill links, agents or settings. Other flags, redirected input or output, and any `CI` value skip the prompts. A missing interactive dependency is installed once with `bun install --frozen-lockfile`; non-interactive installs need no network.

At a terminal the installer ends with one row per tool saying what changed, or that it is up to date, with any `skip`, `left`, `stale`, `note` or `warn` line beneath it. `--verbose` lists every line under its row. Redirected output keeps one line per item on every run.

When Claude Code is installed, it copies `agents/` into `~/.claude`. A personal skill link or agent file with the same name is left alone, and the output lists it on a `skip` line with the reason.

Whenever `~/.codex` (or `CODEX_HOME`) exists, it adds missing skills entries to that directory's `hooks.json`. All four hook entries run the skills CLI through the `AGENTS_DIR` link, which defaults to `~/.agents/skills`. An entry this repository shipped for a retired hook is switched to its replacement in place. Personal entries are left alone. You can rerun it safely. By default, nothing is staged, committed, pushed, or posted unless you turn it on.

The installer writes the [Claude hooks](/agents/claude-code) into Claude Code's `settings.json` (in `CLAUDE_CONFIG_DIR`, else `~/.claude`). It prints the block for a paste only if it refuses the file. With [AGENT_RULES](/reference/configuration#rule-levels) set in `skills.conf`, it also writes strengthening and neutral permission changes there. At a terminal it lists changes for you to confirm under Add, Update and Remove, all ticked. Unticking a rule group saves its override. Unticking a Claude hook saves `CLAUDE_HOOK_<TARGET>=off`; delete that line to re-enable it. Non-terminal runs leave weakening rule changes on a `left` line for you to apply by hand. With `AGENT_RULES` unset or the file refused, it names the reason instead, and `--verbose` prints the rule set to paste. When the Codex directory exists, the same levels write Codex's `rules/skills.rules` ([Codex](/agents/codex#rules)). It removes old shipped hook copies only after rewiring the hooks, and only when every registration it can find can be read and parsed and none names a file under the Claude hooks directory. It reads your Claude settings, your Codex `hooks.json`, and the `.claude/settings.json` and `.claude/settings.local.json` of every project in `~/.claude.json`. Personal files and the directory stay. The installer never creates that directory.
