`install.sh` copies `agents/` into `~/.claude` and prints the hooks block below for you to paste. With [AGENT_RULES](/reference/configuration#rule-levels) set in `skills.conf`, it also manages permission rules in `$CLAUDE_HOME/settings.json`. The agents need nothing more.

## Hooks

Merge the `hooks` key below into `~/.claude/settings.json`, next to any hooks you already have. The commands use the default `AGENTS_DIR`, `~/.agents/skills`. With `AGENTS_DIR` set, point them there instead ([Configuration](/reference/configuration#installer)).

```json
{
  "hooks": {
    "SessionStart": [{ "matcher": "startup|resume|clear|compact", "hooks": [{ "type": "command", "command": "~/.agents/skills/playbook/bin/skills hook session-start" }] }],
    "PreToolUse": [{ "matcher": "^Bash$", "hooks": [{ "type": "command", "command": "~/.agents/skills/playbook/bin/skills hook pre-tool-use" }] }],
    "PostToolUse": [{ "matcher": "^(Edit|MultiEdit|Write)$", "hooks": [
      { "type": "command", "command": "~/.agents/skills/playbook/bin/skills hook post-tool-use" } ] }],
    "Stop": [{ "hooks": [{ "type": "command", "command": "~/.agents/skills/playbook/bin/skills hook stop" }] }]
  }
}
```

What each hook does, and when it stays silent, is on the [Hooks](/hooks) pages, along with the switches that turn them off.

All four hook commands run the skills CLI from the checkout through the `AGENTS_DIR` link, which defaults to `~/.agents/skills`. With `AGENTS_DIR` set, use that directory for all four CLI commands instead.

If your settings already run `~/.claude/hooks/session-brief.sh` on `SessionStart`, replace that command with this one rather than adding it next to it. Both would run, and every session would get the brief twice.

If your PostToolUse settings already run the two comment and dash shims, replace both with the single `skills hook post-tool-use` command above.

If your PreToolUse settings already run the old commit guard shell hook, replace it with `skills hook pre-tool-use` above. Do not add the CLI command beside it.

If your Stop settings already run the old reply guard shell hook, replace it with `skills hook stop` above. Do not add the CLI command beside it.

Each install run names a retired hook your settings still run on a `stale` line. The old copy keeps working until you replace its command, so the line is how you find it.

## Deny Rules

With `AGENT_RULES` set, each install run writes strengthening and neutral permission changes for your delivery mode. Only owned entries change, though formatting can be normalised to the file's indent unit. Weakening changes get a `left` line telling you to edit the file by hand. With the key unset or the file refused, it prints the set and the reason for you to paste into `permissions` instead. [Deny Rules](/delivery/deny-rules) renders the set and says which entry to drop once the commit guard is wired.

Add entries of your own: `EnterWorktree`, and any package manager your lockfile does not sanction, such as `Bash(npm install:*)` in a repository pnpm owns.

A deny rule is an exact prefix match on a tool call, so it does not misfire the way a hook grepping the command string does. A rule in prose is a suggestion. A rule in settings is a rule.

## Agents

The Claude agents in `agents/` load only in Claude Code, from the copies in `~/.claude/agents`. The panel skills (`interrogate`, `how`, `architect`) fan out to them for independent perspectives next to the Codex arms, `/no-comments` sends its reviewer over a diff, and the playbook agent takes delegated work that follows the playbook.
