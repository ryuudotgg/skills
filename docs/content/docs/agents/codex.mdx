Codex runs the same hooks as Claude Code. Every entry runs the skills CLI through the `AGENTS_DIR` link. When `~/.codex` (or `CODEX_HOME`) exists next to a Claude Code install, the installer writes the entries below to its `hooks.json`. Trust new or replaced entries once. The installer replaces both owned comment and dash shims with one `skills hook post-tool-use` command. If you wired the shims yourself, replace both with that command.

It also replaces the owned commit guard and reply guard shell hooks with `skills hook pre-tool-use` and `skills hook stop`. If you wired either yourself, replace it with its CLI command. Do not add the CLI command beside it.

Without a Claude Code install the installer adds no Codex entries. Create `~/.claude` and rerun it to get them.

## Trust the Hooks

Codex records trust per hook definition. Open `codex`, run `/hooks`, and trust the new entries once. A later install run that adds nothing leaves the file untouched, so the trust holds.

## What the Installer Writes

Every entry runs the skills CLI by absolute path under `AGENTS_DIR` ([Configuration](/reference/configuration#installer)). With a home of `/Users/you`, the entries are:

```json
{
  "hooks": {
    "SessionStart": [{ "matcher": "startup|resume|clear|compact", "hooks": [{ "type": "command", "command": "/Users/you/.agents/skills/playbook/bin/skills hook session-start" }] }],
    "PreToolUse": [{ "matcher": "^Bash$", "hooks": [{ "type": "command", "command": "/Users/you/.agents/skills/playbook/bin/skills hook pre-tool-use" }] }],
    "PostToolUse": [{ "matcher": "^(Bash|apply_patch)$", "hooks": [
      { "type": "command", "command": "/Users/you/.agents/skills/playbook/bin/skills hook post-tool-use" } ] }],
    "Stop": [{ "hooks": [{ "type": "command", "command": "/Users/you/.agents/skills/playbook/bin/skills hook stop" }] }]
  }
}
```

- The PostToolUse entry matches `Bash` as well as `apply_patch`, because Codex usually applies a patch by running `apply_patch` through the shell, and hooks see that call as `Bash`. The CLI checks only shell commands that apply a patch and stays silent on every other command.
- Missing entries are added. An entry this repository shipped for a retired hook is switched to its replacement in place and needs trusting again. A personal entry is left alone. The old comment and dash entries are the exception: they sat under `^(Edit|MultiEdit|Write)$`, which Codex never fires for a shell patch, so they are dropped and the CLI entry is added in a group of its own.
- A run that adds or replaces an entry rewrites the file with two space indent, keeping its mode and group, and copying its extended attributes where the system allows. Whether ACLs survive depends on the platform. A run with nothing to change leaves the file untouched.
- A file that is not valid JSON is left alone, and the run prints the entries to add by hand.
- Deleting a skills entry does not stick, since the next install adds it back. To turn the hooks off, set `AGENT_HOOKS=0` ([Configuration](/reference/configuration#hooks-and-skills)). It turns off every hook but the commit guard.

What each hook does, and when it stays silent, is on the [Hooks](/hooks) pages.

<Accordions>
  <Accordion title="Other Files the Installer Leaves Alone">
    The same as invalid JSON, with the entries printed for you: a `hooks.json` that is a directory, a dangling symlink, not UTF-8, not readable, not writable, owned by another user, hard linked, or whose `hooks` key or event lists are not the shape Codex expects.
  </Accordion>
  <Accordion title="A Hook the Installer Skipped">
    A personal retired hook with an entry in `hooks.json` keeps its file and entry. The installer skips its CLI replacement and the output says so.

    If the playbook link points elsewhere, all four CLI entries are skipped and the old entries stay. If Bun is missing, SessionStart, PostToolUse and Stop are skipped the same way, but PreToolUse still gets the commit guard: it denies every shell command until Bun is installed, and the install output says so. Bun is found on PATH, then at `~/.bun/bin/bun`, `/opt/homebrew/bin/bun`, or `/usr/local/bin/bun`.

    If `hooks.json` already runs a personal `session-brief.sh` in the SessionStart event, the installer keeps that entry and skips the CLI entry to avoid a doubled brief. This also applies when a shallow clone or tarball cannot recognise an old copy as shipped. A personal file without an entry does not block the CLI entry.

    The same rule applies to a personal retired commit guard in PreToolUse and a personal retired reply guard in Stop. Its file and entry stay, and the CLI entry is skipped. A personal file without an entry does not block the CLI entry.
  </Accordion>
  <Accordion title="Python 3 Is Missing">
    The installer needs Python 3 to update `hooks.json`, so it prints `skip` and adds nothing. All four hook commands need Bun, not Python 3.
  </Accordion>
</Accordions>
