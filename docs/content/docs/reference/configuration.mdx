## Installer

Prerequisites: git, gh and Bun 1.4.0 or newer. Installing needs no Python.

`install.sh` bootstraps `skills install`, which reads these variables. Paths default under your home directory. Prompts run only with no flags other than `--verbose`, terminal stdin and stdout, and `CI` unset. Delivery mode and optional skills also work non-interactively with `--with` and `--without`. The arm roster works non-interactively with `--arms`. At a terminal the output is one row per tool with what changed and anything that needs a look; `--verbose` lists every line. Redirected output keeps one line per item and prints every block in full.

| Variable      | Default                                                                 | What it does                                                                                                                                                                                                                                                                               |
| ------------- | ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `AGENTS_DIR`  | `~/.agents/skills`                                                      | The canonical store the skills are linked into. All four hook commands run the CLI through its playbook link.                                                                                                                                                                              |
| `CLAUDE_HOME` | `$CLAUDE_CONFIG_DIR`, else `~/.claude`                                  | Where agents are copied, the parent of the Claude Code skills directory, and where retired hook copies are checked. Settings follow `CLAUDE_CONFIG_DIR`, else `~/.claude`, independently of this variable. When it points elsewhere, every run prints a warn line.                         |
| `CODEX_HOME`  | `~/.codex`                                                              | Where missing skills entries are added to `hooks.json`.                                                                                                                                                                                                                                    |
| `SKILLS_CONF` | `~/.agents/skills.conf`                                                 | Where the delivery mode and optional skills are saved. SessionStart, the commit guard and `skills publish` read it in the CLI; the remaining delivery scripts use `skills delivery`. It must be absolute: the installer refuses a relative path, and every reader treats one as hands-off. |
| `SEED_DIRS`   | `$CLAUDE_HOME/skills` and `~/.codex/skills`                             | Space separated skills directories, each created when its parent directory exists. The Codex entry stays `~/.codex` even when `CODEX_HOME` is set.                                                                                                                                         |
| `EXTRA_DIRS`  | `~/.cursor/skills`, `~/.config/opencode/skills` and `~/.copilot/skills` | Space separated skills directories that get links only when they already exist.                                                                                                                                                                                                            |

## Rule Levels

Set `AGENT_RULES` in `~/.agents/skills.conf` to manage Claude Code permission rules and the Codex [rules file](/agents/codex#rules) on each install run. When the Claude or Codex directory exists, the interactive installer sets it through the Deny, Ask, Customize or Don't manage prompt. Customize saves per-group overrides. Choosing Deny or Ask clears those overrides. Don't manage lets you remove owned entries or leave them in place. The [delivery mode](/delivery) selects the recommended set.

| Key           | Value  | What it does                                                             |
| ------------- | ------ | ------------------------------------------------------------------------ |
| `AGENT_RULES` | `deny` | Uses the set's recommended placements.                                   |
| `AGENT_RULES` | `ask`  | Turns recommended deny placements into ask.                              |
| `AGENT_RULES` | `off`  | Recommends no rules unless a group override enables them.                |
| `AGENT_RULES` | unset  | Leaves rules unmanaged and names the reason; `--verbose` prints the set. |

Each per-group key overrides the global level. Its suffix is the group id uppercased, with dashes replaced by underscores. Overrides need `AGENT_RULES` set. Invalid values are noted and skipped.

The installer writes strengthening and neutral changes under `permissions` in Claude Code's `settings.json` (in `CLAUDE_CONFIG_DIR`, else `~/.claude`). Only entries owned by the rule table change. Formatting can be normalised to the file's indent unit. Each changed group gets a `rules` line.

Removing a live deny or ask, moving deny to ask, adding an allow, or rewriting an entry whose placeholder path moved weakens the rules. At a terminal the installer lists changes for you to confirm under Add, Update and Remove, one line per group, all ticked. An interactive install lists every change, a run with flags each group with a weakening change. A group you untick is saved as its override: the placement your file holds for an update when that placement settles the group, `off` otherwise. Choosing Deny or Ask at the rules level prompt clears these overrides like any other. Non-terminal runs leave weakening changes on a `left` line for you to apply by hand. A group at `off` whose entries block what the mode needs gets one `note` line on every run, naming how to lift it. Removing a retired entry is neutral and is applied. If the file is refused, it prints the set and the reason instead. The installer writes Claude hooks before planning rules and prints their block only on refusal. [Deny Rules](/delivery/deny-rules) covers ask's limits and commit guard wiring.

## Claude hook declines

`CLAUDE_HOOK_<TARGET>=off` in `skills.conf` prevents adding or replacing that Claude hook. Targets are `SESSION_START`, `PRE_TOOL_USE`, `POST_TOOL_USE` and `STOP`. Unticking a hook in the drift prompt saves this key. Delete the line to re-enable it. The key does not remove a skills command already in settings or affect Codex hooks. Hooks are managed independently of `AGENT_RULES`.

## Fast Mode

Two optional lines in `skills.conf` turn on fast mode per provider. Both default to `no`. `skills fast-mode` prints the value each one resolves to, with a note for a bad or repeated line.

```
CODEX_FAST_MODE=yes
CLAUDE_FAST_MODE=yes
```

| Key                | What it does                                                                                                                                                                                                           |
| ------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `CODEX_FAST_MODE`  | Runs every Codex arm on the `priority` service tier, through the Codex CLI or a harness such as T3 Code. With `no`, arms pin the `default` tier, since some models default to `priority`.                              |
| `CLAUDE_FAST_MODE` | Runs a Claude arm in fast mode when a harness can, such as T3 Code's `delegate_task` for a model that lists a `fastMode` option. The Task tool has no switch for it, so a Task subagent runs however the session runs. |

## Arm Roster

`ARMS_ROSTER` in `skills.conf` selects the arm families for delegated work. Without the key, the default is Claude and Codex. OpenCode is opt in. The installer asks for the roster after optional skills and reviewers, before rule levels, and keeps the saved choices on reruns. Non-terminal runs leave the roster unchanged unless you pass `--arms`.

The value is a space-separated list of `claude`, `codex`, `opencode` and `<tier>=<provider/model>[#variant]` tokens. Tiers are `luna`, `terra`, `sol` and `astra`. OpenCode requires a `sol` model. Other tiers are optional. A missing tier takes the nearest configured tier above it, but `astra` serves critical work only. Tier tokens require `opencode` in the roster.

```
ARMS_ROSTER=claude opencode terra=opencode-go/glm-5.3#high sol=opencode-go/kimi-k3#max
```

`--arms <value>` or `--arms=<value>` replaces the whole roster and skips the roster questions. At a terminal the installer can still ask you to confirm weakening rule changes. Empty or repeated flags are usage errors. OpenCode choices must match the local `opencode models` and `opencode api model.list` catalog. Invalid choices fail before the installer writes anything.

```bash
./install.sh --arms "claude codex"
./install.sh --arms "claude opencode sol=opencode-go/kimi-k3#max"
```

`skills arms` prints one line per chosen family, including whether its CLI is on `PATH`. It prints only explicitly configured OpenCode tiers, in `luna terra sol astra` order. A last line names who writes the code. For example:

```
claude cli=yes
opencode cli=yes terra=opencode-go/glm-5.3#high sol=opencode-go/kimi-k3#max
implementation=lead
```

Malformed saved tokens are skipped with `arms: ` notes on stderr. A repeated key uses its first row. Without `opencode` on `PATH`, the interactive option is disabled and any saved OpenCode choices stay unchanged. A catalog read failure, or a catalog command that runs past 15 seconds, also keeps saved OpenCode choices. A malformed line elsewhere in `skills.conf` does not change the roster `skills arms` reads.

## Implementation Arm

The lead agent writes the code, and the review arm reads the diff before it ships. `ARMS_IMPLEMENTATION` in `skills.conf` hands every implementation to an arm instead. The value is `lead`, the default, or a family the roster chooses, `codex` or `opencode`. The arm takes the tier the route names for the work.

```
ARMS_IMPLEMENTATION=codex
```

A value outside those three, or a family the roster leaves out, keeps the lead writing and prints an `arms: ` note. The installer does not ask for this key.

## Hooks and Skills

| Variable           | Default                     | What it does                                                                                                                           |
| ------------------ | --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `PLANS_DIR`        | `~/Plans`                   | Where plans and the trail live. The plans skill and the session brief read it.                                                         |
| `AGENT_HOOKS`      | `1`                         | Set to `0` to turn the hooks off. The commit guard ignores it and keeps enforcing the delivery mode.                                   |
| `AGENT_HOOKS_SKIP` | vendored and generated dirs | Comma separated path fragments the comment, dash and reply guard hooks skip. A value replaces the defaults rather than adding to them. |

The `AGENT_HOOKS_SKIP` defaults are `node_modules/`, `/.git/`, `/dist/`, `/build/`, `/out/`, `/target/`, `/vendor/`, `/generated/`, `/.venv/`, `/_archive/` and `/done/`. An empty value uses them too.
