### Authoring or modifying a skill

**You own the skill's voice.** Agent-facing prose has a higher bar than human prose; unhelpful sentences become instructions.

1. Read `../references/writing-for-agents.md` first. It is the reference for how an agent-consumed document is built: how a description's wording decides whether the skill ever fires, the split between always-loaded context load and the human's cognitive load, the ladder from in-file step to in-file reference to disclosed reference, and completion criteria that are checkable rather than vague. Then write the SKILL.md against the frontmatter schema. `name` and `description` are required. Keep `disable-model-invocation: true` wherever it exists and add it to any skill that should not auto-fire; it is what stops a skill taxing every session. `mode`, `icon`, `color` and `reminder` are Cursor chat-mode keys, unsupported here, so never write them and delete them when you find them.
2. Run this skills repo's `scripts/validate.py` against the tree you edited (`python3 <skills checkout>/scripts/validate.py <root>`; the root defaults to the checkout itself) and fix what it reports. Outside a checkout, check the same list by hand. It covers: frontmatter parses, referenced files exist, wrapper agent names resolve, no dashes, and every flag in a `codex` invocation is one the installed CLI accepts. Then check by hand what it cannot: every model and tool the prose names actually exists. Subagent names carry no spaces. `subagent_type` values are hyphenated (`general-purpose`, `playbook-agent`, `codex-sol`). The Task model enum is `sonnet`, `opus`, `fable`; reasoning tier is `effort: low|medium|high|xhigh|max`. A tier outside that enum is not a valid value, and judgment work never silently drops to the cheapest one. Never `readonly:` (not a parameter here, enforce read-only in the prompt), and `background:` is the key, not `is_background:`, which is dropped silently.
3. Test cases if structural; skip if subjective.
4. Prune. Delete any sentence the model already obeys by default, since it pays context for nothing; the arbiter is running the document, not debate, and you delete the whole sentence rather than trimming words. Keep only what the agent cannot find by looking: the unwritten convention, the reason behind a choice, the gotcha no config confesses. Then apply the **no-comments** skill and the three-line style check on every line you wrote: no long dash anywhere, no colon as a mid-sentence connector, one thought per sentence.
5. Run `handing-back.md`.

When in doubt, delete; prose earns its keep by changing a decision. Tell it to do the thing and skip the reason. Explain only when the rule is confusing without one. Match tone to scope. Point at structural sources (types, READMEs, config); hardcoded details go stale (the **encode-lessons-in-structure** principle skill). Delegate to other skills by path; don't restate. A workflow you keep hitting but isn't captured: first name the skill or playbook that owns the nearest case and say why extending it fails. Only then propose a new skill; most candidates are an existing one missing a sentence.

**Reply:** summary of the skill, key design decisions, validation notes.
