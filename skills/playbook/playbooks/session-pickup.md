### Session pickup

**You own the resume point. Read the prior trail, don't redo it.** For "take over this", "resume this conversation", "continue from <transcript path>", "you're taking over", "pick up where X left off", or a branch you're meant to continue.

A pickup is inheritance. The prior agent already paid the cost of reading the code, running the repros, making the design choices. Redoing loses the bias check and burns context. Resist the urge to re-derive; read.

**Foreign work** is a PR or branch with no plans row in any index and no publish mark (`git config --get branch.<name>.skills-owned` printing `true`): someone else wrote it. Treat the handoff as context, not proof, so the inherited claims get verified before anything builds on them. State the goal in one line before reading the diff, from the PR title and its commit subjects, or from the commit subjects alone when there is no PR, and name the author: the PR author, else the commits' author. Then look for work that already does it with a read only `gh pr list --state all --search "<goal terms>"`. When trunk already does it, the pickup ends with `superseded by <short sha>`, naming the commit that landed it. Otherwise fetch the source head, `git fetch origin <branch>` or `git fetch origin pull/<number>/head` for a PR, note its sha, and cut a fresh local branch from it with `git switch --no-track -c <type>/<desc> FETCH_HEAD`, so every inherited commit keeps its sha and author. The name is never the source's and is one neither this clone nor origin holds yet (`git ls-remote --heads origin <type>/<desc>` prints nothing), since `skills publish` pushes onto a name origin already has and marks only a branch its own push created. No inherited commit is cherry-picked, rebased or amended by hand, in either mode. Your fixes land on top under `../references/delivery.md`: unstaged in hands-off mode, and in prs mode through `../bin/skills publish`, which gives the branch its publish mark, then the normal babysit. A stale base goes through `../bin/skills restack-layer` with no `-P`, the one verb that replays inherited commits, keeping their authors but not their shas. Until that publish the branch is not owned, and no plans row or plan file is written for it. Before publishing, fetch the source again: a head that moved stops the takeover with both heads reported, and the takeover restarts from the new head. The source PR, its branch, its threads and its state stay untouched. Steps 2 to 5 run from here, and the handback names the source PR, or the branch and that it has no PR, and its author.

1. Locate the prior trail. Transcripts live at `~/.claude/projects/<encoded-cwd>/<sessionId>.jsonl`, where the encoded cwd is the absolute path with every character other than an ASCII letter or digit (`A` to `Z`, `a` to `z`, `0` to `9`) turned into a hyphen (`/Users/you/Projects/app` becomes `-Users-you-Projects-app`, `/Users/you/.t3/worktrees/app` becomes `-Users-you--t3-worktrees-app`). Resolve the directory from the current cwd and read the specific session file. Do not glob across `~/.claude/projects/*/`, that crosses project boundaries and reads private chats from unrelated work. Do not glob inside the directory either; `memory/` sits in it, so a naive `*` ingests non-transcripts. A paused run instead leaves `.resume-<id>.md` and `.resume-<id>.patch` in the plans directory (default `~/Plans`, override with `PLANS_DIR`) under `<plans>/<Project>/`; read the note first when one exists. A plan adopted from another machine with `skills plans adopt` is picked up by `/plans do <id>`, never by a fresh start: the note adopt wrote is its trail, and the adopted commits and uncommitted diff are the work already done. Read the metadata overview and last messages first, then scan back for the decision points. Parse a long transcript in a subagent and keep the reduced timeline in the main thread (the **guard-the-context-window** principle skill).
2. Reconstruct operational state. The branch, what already landed (`git log`, `git diff` against the base), what is still unstaged in the tree, the open todos, the decisions made. Recover the delivery mode by running `../bin/skills delivery` by its absolute path, per `../references/delivery.md`, and any open PR or stack for the branch: `gh pr list --head <branch> --state open --json number,url,baseRefName` for the branch and its parent, following `baseRefName` down to trunk and `gh pr list --base <branch> --state open` up, one layer at a time. The prior trail is authoritative input. Resist the bias to re-derive it. The one exception is a constraint the trail never recorded: re-derive that rather than assume it was never given, and where it decides a destination or visibility (which surface, which tab, public or private, who can see it), stop and ask the operator instead.
3. Diff done vs pending. Compare what shipped against what was planned, name the resume point, do not re-run the prior repro or redo completed work. A "let me verify from scratch" pass is the tell that you're treating the trail as untrustworthy when it's actually authoritative.
4. Route the remaining work to the matching playbook and pick the verdict: continue the execution, ship a finished recommendation, ratify or override a prior conclusion, or postmortem a failed run. The pickup playbook ends here; the routed playbook owns the rest.
5. Verify the inherited claims against the original goal on the real artifact (the **prove-it-works** principle skill). A passing prior self-report is not the proof.

**Reply:** where the prior agent stopped, what you inherited vs redid (ideally nothing redone), the resume point, and the outcome.
