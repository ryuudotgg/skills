`plans set-row`, `plans add`, `plans log` and `plans lint` without `--overlap` touch only files under the plans directory, never git or a remote, with one exception: in prs mode `plans set-row` to REVIEW first reads the row's PR with `gh` and refuses, writing nothing, unless it is green and mergeable or already merged. `plans lint --overlap` reruns each open plan's `rg` probe commands read only, on the same tree and under the same limits as `plans wave`, and writes nothing. `plans frontier` reads git only to detect the project when none is passed. `plans chain` prints a branch's recorded base chain, bottom first, from git config. `plans handoff` reads the checkout name and the recorded bases from git and writes nothing, neither the index nor the log. `plans stack-base` asks `gh` about blocker PRs, fetches the remote default branch, and with `--cut` creates the plan's branch. `plans below` reads the base's chain through `plans chain`, then that chain's open PRs and their unresolved threads an installed reviewer started with `gh`, and writes nothing. `plans wave` reruns the `rg` probe commands of each ready, DOING and REVIEW plan read only, on a temporary export of the remote default branch the threads start from (the checkout itself when no `origin/HEAD` is set), refusing any flag outside a short list and any path outside the repo, reads the wave settings from the skills config and the store's leases, holding a ready plan another device has pinned or whose lease is in conflict, and writes nothing, with or without `--dry-run`. `plans resume` reads `PLANS_RESUME_EVERY` from the skills config, the index and the log, and with `--facts` the thread facts on stdin, and writes nothing. `plans schedule` reads `AUDIT_DIGEST`, `PLANS_RESUME_EVERY`, `PLANS_SWEEP_EVERY`, `THREADS_RESUME_EVERY` and `DIGEST_WEEKLY` from the skills config and writes nothing; with no project it detects one, and runs without one when none matches. `threads resume` reads `THREADS_RESUME_EVERY` from the skills config, the ad hoc trail in the log, each branch's publish mark, every plans index and the open PRs with `gh`, and with `--facts` the thread facts on stdin, and writes nothing. `plans start` runs `plans stack-base`, the `plans below` preflight in prs mode, the cut, `plans set-row` and `plans log` as one command. `plans close` writes the row, moves the plan file into `done/` and appends the log line. `plans sweep` reads each DOING and REVIEW row's PRs with `gh`, the checkouts with `git worktree list`, and `log.tsv`, closes the merged rows through the same code as `plans close`, and removes the closed rows' `/tmp/plans-<id>/` directories; with `--dry-run` it writes and removes nothing. `plans release` reads the same candidate checkouts the sweep's `checkout` lines list, each one's merged PR head with `gh`, or the newest PR's head when none merged, `log.tsv`, `PLANS_DISPOSABLE` from the skills config and the working directories of the operator's processes with `lsof`, reads every hold again under the scratch lock, and runs `git worktree remove` without `--force` on each checkout none of them holds, never touching a branch; with `--dry-run` it removes nothing. With `--facts` it first reads harness facts on stdin, a JSON array of `{"path": "<checkout>", "live": <bool>}` entries, refuses with exit 2 before any removal when they are not one, and holds every candidate whose entry is missing, malformed, listed twice or `live: true`. `skills reap` lists the simulators with `xcrun`, the AVDs with `emulator` and `adb`, the compose projects and volumes with `docker` and the TCP listeners with `lsof` and `ps`, reads each one's owner from its name or working directory, and stops then deletes each one whose owner is a DONE or DROPPED row of the project, a legacy id such a row holds, or an ad hoc branch whose last trail event is `handback`, reading every hold again under the scratch lock before each stop and each delete; it never touches an artifact with no owner, nor the caller or its ancestors, and with `--dry-run` it stops and deletes nothing. With `--mine` in place of the project it detects the project, takes the checkout's owner (every open row holding the current branch, else the lowest closed one and the ad hoc branch, else the ad hoc branch), refuses on the default branch, a detached HEAD or a checkout whose names match two projects, and reaps every artifact that owner holds even while its own row is open, but keeps one that another owner sharing its name still holds. `skills device` resolves the checkout's owner the same way and refuses where it has none, then prints the UDID or emulator serial of that owner's booted device of the type, finding it by name, creating it with `xcrun simctl create` or by writing the AVD files, and booting it, under a lock per device, so it touches only the devices its own owner's name names. `skills machine show` prints this machine's newest facts from the store (label, device id, T3 environment id, OS, architecture, each tool's version or why it is absent, the checkout recorded for each project, and when they were captured), with `--json` as one object, and writes nothing. `skills machine refresh` probes the OS, the tools and the checkout it runs in, keeps every recorded checkout whose path still exists, and writes one `machine` event to the store under `<plans>/.machine.lock`; `--environment` records the T3 environment id with it, and a refresh without the flag keeps the recorded one. `skills machine label` writes a `machine` event that replaces the default label, the computer name on macOS or the hostname on Linux. `plans move` hands a DOING plan to another machine: it reads the row, the branch's recorded base and `<plans>/<Project>/.resume-<id>.md`, refusing when the note is missing, packs the commits since the base, the tracked diff, the untracked files and the note into one archive under `/tmp/plans-<id>/`, uploads it through the hub to the device `--to` names (any device without the flag) or writes it to the new file `--file` names, then records a `moved` event and releases the plan's lease in one transaction. It never touches the branch or the working tree, and a failed upload records nothing. Until a machine adopts it, the frontier marks the row `(moving to <target or any>)` and `plans start` refuses it on every machine but the target. `plans adopt` takes a moved plan onto this machine, from the hub or from the file `--file` names. It checks the archive against the `moved` record, then refuses, before any ref or working tree change, on a lease another machine holds, a dirty tree, an existing branch or a base origin lacks. Otherwise, in the checkout this machine's facts record for the project, it takes the lease, creates the branch at its base with the base recorded in git config, applies the commits, the diff and the untracked files, writes the resume note, sets the row DOING on that branch, logs `start` and records `adopted`, undoing all of it when any step fails. It prints `adopted <Project> <id> into <checkout> on <branch>`, then the `/plans do <id>` line that resumes it, then, for each session `skills sessions list --plan <Project>/<id>` returns whose policy is `redacted` or `full`, `Session <host> <session>` and the redacted digest of that session's newest transcript chunk, read from the store since the transcript itself is on the other machine, or `digest: blob missing` when no sync has brought that digest yet. Neither verb runs unasked, since both change which machine holds the plan: `plans move` runs only from the Pause safely playbook when the operator named a target, and `plans adopt` only when the operator asks for it. All of them resolve `${PLANS_DIR:-$HOME/Plans}` themselves. `plans set-row`, `plans add`, `plans start`, `plans adopt`, `plans close` and `plans sweep` are the only index writers, and they, `plans log` and `threads log` the only trail writers: each commits its row change and trail lines to the store in one transaction, then rewrites the views it touched by rename, so threads writing at once lose no row and no line. Whichever of them first finds no `plans.db` runs `plans import` before anything else, `plans start` before it touches git, and exits nonzero when that import refuses. `plans set-row` stamps `updated` and truncates the note to 100 chars. `plans add` appends a TODO row and prints it. It takes the id of the `NNN-<slug>.md` already on disk, or the next id past every row and plan file when there is none, and refuses an id or a slug another row already holds. Rerun on a row it already added, it prints that row again. `plans log` refuses an event outside `start`, `review`, `handback`, `done`, `thread`, `wave`, `nudge` and `conflict-sent`, or outside `start`, `handback` and `nudge` for the ad hoc id `-`, naming them, and creates `log.tsv` with its header on first use. `plans import` reads every `index.tsv`, `log.tsv` and plan and ctx file into `<plans>/plans.db`, checks that the store renders both views byte for byte, and on a rerun adds only what changed; it refuses, naming the file and line, a view that does not round trip, a row deleted from a view the store holds, a line edited after it was imported, or a view edited while a write to it was unfinished, and writes nothing outside `plans.db`, its journal and its lock, except that a view the store holds that went missing is written back from the store. Moving an edited view aside and running `plans import` again is the way out of every refusal that cannot take the edit in. Every plans verb above that reads rows or the trail, and the session start hook, reads them from the store, runs that same first import when there is no `plans.db`, and needs neither view to exist; a header only `index.tsv` the store has not seen yet reads as an empty project, so a new project works before its first `plans add`. A store that cannot open, or a first import that refuses, makes the reader refuse with the reason, which the session brief prints in place of its plans lines. `plans sweep`, `plans release` and `skills reap` also refuse while a view holds an edit made outside the store, naming `skills plans import`. Plan and ctx files, `done/` included, are working copies: `skills brief`, `plans lint`, `plans lint --overlap`, `plans wave`, `plans frontier` without `--at`, `plans start`, `plans stack-base`, `plans close` and `plans sweep` record each one they read as a revision in the store before reading it, when its bytes differ from the last revision at that path, and `plans close` also records the copy it moves to `done/`, stamped on DONE, refusing with a retry when the file changed while it waited. Recording a revision is the one store write these verbs make on a dry run or a read only pass, so "writes nothing" above means nothing beyond it. `plans history` prints one line per revision of a plan or ctx file, oldest first and across the move into `done/`: the recorded time, the sha256, the machine id and the byte count. `plans show` prints the newest revision, or with `--at` the newest one recorded at or before an ISO 8601 UTC time or the end of a `YYYY-MM-DD` UTC day. `plans show --conflict` prints the other machine's copy of a plan or ctx file the hub sync kept because both machines changed it, and refuses while that copy is still fetching or when there is none. `plans frontier --at` prints the frontier from the rows the store held at such a time, alone or with `--next` or `--stacks-on`, and refuses a time before the store first held the project, naming when it did. `plans checkout` writes the newest revision back to a missing working copy and prints `<path> written`, prints `<path> current` when the file already matches it, and refuses, naming the file and changing nothing, when the file differs or another path holds the plan. All three only read the store, after the first import when there is no `plans.db`, and only `checkout` writes a file.
